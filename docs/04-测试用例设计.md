# 测试用例设计（核心模块节选）

设计方法说明：输入域类（登录、加购数量）用**等价类划分 + 边界值分析**；流程类（下单支付）用**场景法**；规则类（优惠券）用**判定表**思路；再叠加异常（弱网/重复提交/越权）与接口维度。

## 1. 登录模块（等价类 + 边界值）

| 用例ID | 场景 | 输入 | 预期 | 优先级 |
|---|---|---|---|---|
| LOGIN-01 | 有效等价类 | 正确用户名+正确密码 | code=0，返回 token | P0 |
| LOGIN-02 | 无效等价类-密码错 | 正确用户名+错误密码 | code=1003 | P0 |
| LOGIN-03 | 无效等价类-用户不存在 | 未注册用户名 | code=1002 | P1 |
| LOGIN-04 | 无效等价类-空 | 用户名为空/密码为空/均空 | code=1001 | P0 |
| LOGIN-05 | 边界-超长 | 用户名 1000 字符 | 不崩溃，明确报错 | P2 |
| LOGIN-06 | 安全-SQL注入 | username = `' or 1=1--` | 登录失败，不泄露信息 | P1 |
| LOGIN-07 | 幂等 | 同一账号连续登录 | 均成功，token 各自有效 | P2 |

## 2. 购物车数量（边界值分析，需求 FR-301：正整数且 ≤ 库存）

库存商品 3 号 = 5 件。边界点：0、1、5、6。

| 用例ID | 输入 quantity | 预期 | 优先级 |
|---|---|---|---|
| CART-01 | 1（有效最小值） | 加购成功 | P0 |
| CART-02 | 5（= 库存上限） | 加购成功 | P0 |
| CART-03 | 6（> 库存） | code=2003 库存不足 | P0 |
| CART-04 | **0（无效边界）** | **应拒绝** | P0 |
| CART-05 | **-1（无效等价类）** | **应拒绝** | P0 |
| CART-06 | 1.5（小数）/"a"（非数字） | code=2002 | P1 |
| CART-07 | 未登录加购 | code=401 | P0 |

> CART-04/05 执行结果：**实际未拒绝 → 缺陷 BUG-001**。

## 3. 优惠券门槛（边界值，需求 FR-402：满 30.00 含本数减 10）

商品：显示器支架 30.00 元 / 无线鼠标 59.90 元。

| 用例ID | 订单金额 | 用券 | 预期 | 优先级 |
|---|---|---|---|---|
| CP-01 | **恰好 30.00（门槛值）** | MAN30JIAN10 | **用券成功，实付 20.00** | P0 |
| CP-02 | 30.01（门槛+0.01） | MAN30JIAN10 | 用券成功 | P1 |
| CP-03 | 29.99（门槛-0.01） | MAN30JIAN10 | code=3002 未达门槛 | P0 |
| CP-04 | 任意金额 | 不存在的券码 | code=3002 优惠券不存在 | P1 |
| CP-05 | 金额校验 | 用券后 | 实付 = 合计 − 10.00，精确到分 | P0 |

> CP-01 执行结果：**30.00 整被提示"未达门槛" → 缺陷 BUG-002**（开发把 `>=` 写成了 `>`，评审时的疑问命中）。

## 4. 下单-支付主流程（场景法）

| 用例ID | 场景 | 预期 | 优先级 |
|---|---|---|---|
| ORD-01 | 基本流：登录→加购→下单→支付 | 订单"已支付"，库存扣减，购物车清空 | P0 |
| ORD-02 | 备选流：购物车为空直接下单 | code=3001 | P0 |
| ORD-03 | 备选流：重复支付已支付订单 | code=4003 | P0 |
| ORD-04 | **异常流：同一购物车重复提交下单**（双击/重试） | **只生成一笔订单**（FR-403 幂等） | P0 |
| ORD-05 | 异常流：支付他人订单 | code=4002 越权拦截 | P0 |
| ORD-06 | 异常流：无 token 下单 | code=401 | P0 |
| ORD-07 | 数据一致性 | 下单后商品库存 = 原库存 − 购买数 | P0 |

> ORD-04 执行结果：**生成两笔订单 → 缺陷 BUG-003**（幂等未实现，评审疑问再次命中）。

## 5. 弱网与中断专项（Charles 辅助，详见 06-抓包测试实践）

| 用例ID | 场景 | 预期 |
|---|---|---|
| NET-01 | 3G 弱网（Charles Throttle）下单 | 正常完成或明确超时提示，无脏数据 |
| NET-02 | 下单请求发出后断网 | 订单状态一致：要么不存在，要么"待支付"，不允许"钱扣了没订单" |
| NET-03 | 弱网下快速重复点击提交 | 不产生重复订单（与 ORD-04 互证） |
