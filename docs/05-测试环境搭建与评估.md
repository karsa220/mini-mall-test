# 测试环境搭建与评估

## 1. 环境架构

```
测试机 (Windows 11)
├── Python 3.13 venv（隔离依赖，不污染系统环境）
│   ├── flask          被测服务 MiniMall（127.0.0.1:5000）
│   └── pytest/requests/pyyaml   自动化测试框架
└── Charles（8888 端口，弱网/抓包专项）
```

## 2. 搭建步骤

```bash
# 1. 创建独立虚拟环境（依赖隔离）
python -m venv .venv
source .venv/Scripts/activate        # Windows Git Bash

# 2. 安装被测系统与测试框架依赖
pip install flask pytest requests pyyaml

# 3. 启动被测服务
python app/server.py                 # 监听 127.0.0.1:5000

# 4. 环境自检（冒烟）
curl http://127.0.0.1:5000/api/products
# 返回 code=0 即环境就绪
```

## 3. 环境评估结论

| 评估项 | 结论 | 说明 |
|---|---|---|
| 与生产环境差异 | 可接受（本期） | 生产为 Linux + MySQL + Nginx，测试环境为 Windows + 内存存储；**功能逻辑一致，但数据持久化、并发能力不可类比**，故性能测试不在本环境做 |
| 数据管理 | 风险已知 | 内存存储重启即重置 → 所有自动化用例**自造数据**（setup 里登录、加购），不依赖预置数据，保证可重复执行 |
| 环境隔离 | 达标 | venv 隔离 Python 依赖；服务独立端口；Charles 代理仅按需开启，避免影响系统流量 |
| 可维护性 | 达标 | requirements.txt 锁定依赖，新机器 10 分钟可复现环境 |

## 4. 已知环境局限（写进报告，避免误判）

1. 内存存储 → 无法测试"服务重启后订单是否还在"（持久化问题不在本期）。
2. 单进程 → 并发测试结果仅作功能幂等参考，不代表生产并发能力。
3. mock 支付 → 真实支付渠道（微信/支付宝回调）未覆盖，列为遗留风险。
