# MiniMall V1.0 测试计划

## 1. 测试范围

| 范围 | 内容 |
|---|---|
| 本期测试 | 登录、商品、购物车、下单（含优惠券）、支付的**功能测试**；核心链路**接口自动化**；**弱网专项**；安全基础项（鉴权、越权） |
| 本期不测 | UI/兼容性（无前端页面）、性能压测（单机内存版）、支付真实渠道（mock 支付） |

## 2. 测试策略

| 测试类型 | 方法 | 通过标准 |
|---|---|---|
| 功能测试 | 等价类划分 + 边界值分析 + 场景法设计用例，手工执行 | 用例 100% 执行，致命/严重缺陷为 0 |
| 接口自动化 | pytest + requests + YAML 数据驱动，覆盖登录与下单全链路 | 除已知缺陷（xfail）外全部通过 |
| 弱网专项 | Charles Throttle 模拟 3G/高延迟/丢包 | 无重复下单、无脏数据、错误提示明确 |
| 安全基础 | 抓包检查敏感信息、无 token 访问、操作他人订单 | 无明文敏感信息、越权被拦截 |
| 回归测试 | 缺陷修复后执行全量自动化 + 受影响模块手工用例 | 缺陷关闭，无新增问题 |

## 3. 进度安排

| 阶段 | 时间 | 产出 |
|---|---|---|
| 需求评审 | D1 | 评审记录，确认可测性 |
| 用例设计与评审 | D1–D2 | 测试用例 60+ 条 |
| 环境搭建 | D2 | 测试环境就绪（见环境搭建文档） |
| 手工功能测试 | D3–D4 | 执行记录、缺陷单 |
| 接口自动化开发 | D3–D5 | 自动化脚本，纳入每日回归 |
| 弱网/安全专项 | D5 | 专项测试记录（Charles 实践文档） |
| 回归与报告 | D6 | 测试报告，上线结论 |

## 4. 资源与环境

- 人力：测试 1 人（本人，独立负责交易链路方向）
- 环境：Windows 11 + Python 3.13 venv；被测服务 127.0.0.1:5000；工具 Charles / pytest / requests
- 数据：测试账号 test01/test02；商品 3 个 SKU；优惠券 MAN30JIAN10

## 5. 风险与应对

| 风险 | 应对 |
|---|---|
| 需求变更（优惠券规则调整） | 用例参数化（YAML 数据驱动），改数据不改脚本 |
| 提测延期压缩测试时间 | 优先级排序：核心交易链路用例 P0 先测，自动化兜底回归 |
| 环境不稳定（内存数据重启丢失） | 用例设计为自造数据（setup 自动登录/加购），不依赖预置数据 |

## 6. 准入准出标准

- **提测准入**：开发自测通过、接口文档齐、冒烟用例（登录→下单→支付）通过
- **上线准出**：P0/P1 用例 100% 通过，无未关闭的致命/严重缺陷，一般缺陷有规避方案或排期
