# 字节跳动测试开发（测开）JD 与面经收集

> 用途：把 MiniMall 项目升级为「企业级测试」的对标依据。下面内容来自公开 JD 与牛客/面经社区的高频真题梳理（2025–2026）。
> 关键结论：字节测开早已不是"会写自动化脚本"，而是 **工程效能 + AI 测试 + 底层技术 + 业务架构** 四维综合能力。

---

## 一、JD 职责与技能要求（官方岗位提炼）

**典型职责（数据平台 / 电商 / 飞书等多条线共性）**
- 自动化测试体系建设与推广
- 参与构建 **自动化测试平台、性能测试平台、持续集成平台**
- 测试工具研发、效率工具研发
- 测试用例编写、**性能测试、压力测试、高可用测试**（提升稳定性/可用性/核心性能）

**硬性技能要求**
- 语言：Java / Python / Go 至少一门；熟悉 MySQL、MongoDB 等数据库
- 服务端开发工具链；Linux；Docker 优先
- 框架工具（JD 明确点名）：RobotFramework、TestNG、Jenkins、**JMeter**、Selenium、Nose、**Locust**（二次开发经验尤佳）
- 熟悉测试流程与用例设计方法，能主动技术钻研、流程优化

**新方向（2026 趋势）**：AIGC 评测、LLM 应用、Agent、智能测试（AI 用例生成 / AI 自动化 / 质量预警）

## 二、面经高频考点（按轮次/主题归类）

### 第 1 轮：基础技术面（计算机基础 + 手写代码 + 测试设计）
- **八股**：进程/线程/协程区别；TCP 三次握手四次挥手、TIME_WAIT；HTTP/1.1 vs HTTP/2 vs HTTP/3/QUIC；MySQL 索引为什么用 B+ 树、最左前缀；事务 ACID
- **手写算法（超高频）**：两数之和、LRU 缓存（O(1)）、链表环/入口、二叉树层序、最长无重复子串、最长回文子串、快排/归并、线程安全单例
- **测试设计**：登录（用户名+密码+验证码）、视频播放器（弱网/横竖屏/后台切换）、计算器 APP 的测试维度

### 第 2 轮：项目深挖 + 测试方案设计
- 挑一个最有挑战的项目深挖 30 分钟（实现细节、踩坑、改进）
- 业务场景测试设计（含自动化/性能/稳定性/AI 评测）
- 高频追问：**"你的自动化框架怎么做的"**、失败用例怎么排查、**用例间数据污染怎么解决**、造数工具局限性、**最值得的 Bug**
- AI 场景：如何为豆包/大模型应用设计评测体系、解决 LLM 输出不稳定

### 第 3 轮：算法 + 系统设计
- 算法：最长回文子串、岛屿数量（DFS/BFS）、课程表（拓扑）、用两栈实现队列、O(1) 随机数据结构
- 系统设计（2026 偏向 AI/工程效能）：
  - **设计一个分布式压测平台（百万级并发）**
  - **设计一个精准测试系统**（代码变更自动推荐用例）
  - **设计一个 LLM 应用自动化测试框架**

### 第 4 轮：主管/交叉面（开放题）
- "如何为抖音直播/电商大促设计质量保障体系"
- "测试开发的核心价值是什么？未来 5 年会被 AI 替代吗？"
- "讲一个你推动技术改进/流程优化的案例，遇到什么阻力、怎么解决"

### 面经里出现的具体追问（可直接对标本项目）
- 性能测试**关注哪些参数**、怎么**分析瓶颈**、容量规划怎么做
- **如何模拟封控/异常场景**、支付失败原因有哪些
- **幂等性**怎么做的、为什么用 INCR、RabbitMQ 与 Kafka 区别
- Session 与 Token 区别、哪个更安全
- 接口测试的参数设计、依赖第三方接口怎么处理、**测试数据放哪**、什么是数据驱动
- 印象最深的 Bug、如何保证自己的工作质量

## 四、JD 逐条对标（全生命周期 / 数据分析 / 工具平台 / 质量体系）

> 针对常见测开 JD 的第 2~5 条逐条映射到 MiniMall 的可验证产出。

**第 2 条 · 深度参与产品研发全生命周期（功能/自动化/性能/安全/专项/稳定性监控/流程改进）**

| JD 手段 | MiniMall 落地 | 证据 |
|---|---|---|
| 功能测试 | 7 领域 22 端点正反/边界用例 | test_component.py（38 例） |
| 自动化实施 | 四层测试金字塔 + Appium 真机 UI | test_*.py / test_appium_*.py |
| 性能测试 | Locust 主链路压测 + p95/错误率阈值 | perf_test.py / run_perf_check.py |
| 安全测试 | 越权/伪造token/SQL注入/弱口令/暴力破解限流 | test_security.py（7 例） |
| 专项测试 | 混沌故障注入（应用级 + 网络级 504） | run_chaos_check.py |
| 稳定性监控 | `/metrics` 采集 QPS/错误率/时延 | server.py /metrics |

**第 3 条 · 通过质量和效率数据分析，持续完善产品质量与用户体验**
- 质量数据源：`/metrics`（时延/错误率）、`perf_report.json`（p95）、`chaos_report.json`（故障感知）、`coverage.xml`（覆盖率）
- 数据落地：`Jenkinsfile` 的「质量度量归档」stage 汇总为仪表盘输入（可接 Grafana/Prometheus）
- 效率数据：并行执行把回归从 30min 压到 ~2min（四层并行 + 企业级门禁并行）

**第 4 条 · 通过工具/平台开发提升研发效率、完善质量保障策略**
- `data_factory.py`：测试数据工厂（合成数据 + 命名空间隔离）
- `run_perf_check.py` / `run_chaos_check.py`：自包含门禁 runner（起服务→压测/注入→断言→退出码）
- `har_contract_diff.py`：接口契约回归工具（破坏性变更自动报警）

**第 5 条 · 参与质量体系规划建设，实施自动化/无人值守/智能测试/故障演练**
- 无人值守：Jenkins 定时夜间跑 + 失败自动建 Jira bug
- 故障演练：`/api/chaos` 故障注入 + 幂等重试正例验证（等价于混沌工程演练）
- 质量门禁：覆盖率 80% + 性能 + 混沌三重卡口，fail fast
